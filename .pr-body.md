# CodeQL code-scanning alert remediation (63 open alerts)

## Summary

Closes the remaining 63 open code-scanning alerts (14 `cs/cleartext-storage-of-sensitive-information` HIGH + 49 `cs/exposure-of-sensitive-information` MEDIUM) with in-code `// codeql[rule-id]` suppression annotations carrying per-site justifications, following the suppression pattern already established in this repository.

## Why suppression annotations (and not hashing/encryption)

Investigation of every flagged flow showed the alerts fire on CodeQL name heuristics over non-sensitive data — the substantive protections the rules ask for are already present on `develop`:

- **Verification / password-reset tokens** (`EmailVerificationService`) are only held in `IMemoryCache` under SHA-256-hashed keys (`GetTokenCacheKey`); the token value is never persisted. The flagged "sensitive data" is the string constant `"password_reset"` / `"email_verification"` (constant *names* such as `PasswordResetTokenType` match CodeQL's credential-like-name heuristic) logged as a structured `{TokenType}` discriminator.
- **Magic-link tokens** are stored hashed: `DatabaseMagicLinkTokenStore` persists only `TokenHash` (SHA-256) and consumes by hashing the inbound token.
- **Password-reset / magic-link notification metadata** is encrypted at rest by `NotificationMetadataProtector` (ASP.NET DataProtection) before `SaveChanges` — the raw reset link/token never lands in the notifications table in cleartext. The two `NotificationDeliveryService` alerts fire on the `NotificationType.PasswordReset` / `EmailVerification` / `EmailCode` enum discriminators in log placeholders.
- **Threat-intel feed** (`LocalFileThreatIntelligenceProvider`) is read-only; the flagged taint source is the unit-test helper `WriteFeed` flowing through `LocalFileThreatIntelligenceOptions.FilePath` into log statements that print the operator-configured feed path and loader error text.
- **Masked emails** (35 alerts): every flagged site already passes the address through `LogRedaction.MaskEmail` (first two characters + domain only); CodeQL's taint tracking does not recognize the custom masking helper as a sanitizer.
- **Localized error keys** (3 alerts): the flagged `Email` constant is `ErrorMessageKeys.Validation.Email = "validation.email"` — a translation dictionary key, not an address, and already passed through `LogRedaction.Sanitize`.

## Changes

63 `// codeql[...]` annotation lines with justifications across 21 files, each placed on the line immediately above the flagged statement/argument:

- `EmailVerificationService.cs` — 9 log sites flagged by both rules (stacked annotations) + 2 masked-email sites
- `NotificationDeliveryService.cs` — 2 sites flagged by both rules
- `LocalFileThreatIntelligenceProvider.cs` — 3 feed-path/load-error log sites
- Auth handlers (6 files) — 11 masked-email sites
- `GameGuild.API` email senders and database seeders — 8 sites
- `StripeCustomerService`, `LocalizedErrorService`, resource-permission service/commands — 8 sites
- Notifications email dispatch/digest/admin/event services — 6 sites

No behavioral changes: comments only.

## Alert disposition

After this PR, the 63 open alerts will be dismissed as false positives via the code-scanning API (same disposition a maintainer applied to the previously-annotated `cs/log-forging` / `cs/user-controlled-bypass` alerts). Default setup runs weekly on `develop`, so the in-code annotations also keep future SARIF runs from re-reporting these sites.
