# Fix broken client calls: MFA enrollment route, promo dashboard prefix, sign-in via the generated client

Fixes #1217

Findings F1/F2 (+F5 verification and the F3/F4 sign-in slice) from
`docs/architecture/api-contract-matrix.md`.

## F1 — MFA enrollment posted to an unserved route

`packages/infrastructure/client/src/integrations/next/handlers.ts` shipped a
`POST /api/auth/mfa/enrollment` action that fetched
`${apiUrl}/v1/auth/mfa/sign-in/enrollment` — a route no controller serves. The
API removed that endpoint in #838 (`5f9e18a99a`, "remove sign-in enrollment
endpoint — enrollment lives in settings"), but the client-side route-case was
left behind posting into the void: every caller got a 404.

The handler now calls the real enrollment surface — `POST /v1/auth/mfa/totp:setup`
(`MfaController.cs:54`) — through the generated
`AuthMultiFactorModule.postAuthMfaTotpSetup()`, authenticated with the caller's
session token (enrollment is a settings-time operation per #838). Callers
without an authenticated session get a 401 `MfaEnrollment` error instead of a
guaranteed 404. The provisioning-only response contract
(`{ success, secretKey, qrCodeUri, expiresAt }`) and the no-session-cookie /
`no-store` guarantees are unchanged.

## F2 — promo dashboard fetched `/api/v1/...` where the API serves `/v1/...`

`apps/web/src/app/api/billing/promo-campaigns/route.ts` and the console page
fetched `${apiBaseUrl()}/api/v1/promo-campaigns...` while the controller route is
`v{version}/promo-campaigns` — the dashboard silently rendered empty
(`if (!response.ok) return [];`).

Both now load through the generated `CommerceProductsPromoCampaignsModule`
(list, performance report, and the four lifecycle transitions), and failures
surface instead of vanishing:

- the proxy maps upstream rejections to their status, and generated-client
  contract-drift throws (safeParse, issue #864) to 502;
- the page renders the repo's established destructive-alert fallback
  (`Alert variant="destructive"`, like the invitations and email-deliverability
  pages) instead of an empty table — a legitimate empty list still renders the
  console with its empty state.

## F3/F4 (partial) — password sign-in through the generated client

`packages/infrastructure/client/src/runtime/auth/providers/credentials.ts`
hand-rolled `fetch` posts to `/v1/auth/sign-in` and
`/v1/auth/mfa/sign-in/complete`. The Turnstile hardening (#1082, `d3e340865`)
added `turnstileToken` to that raw body and to the generated contract — but the
runtime kept posting by hand, so the next CAPTCHA change could again ship
outside the typed pipeline (matrix F4).

The provider now calls `AuthModule.postAuthSignIn` /
`AuthModule.postAuthMfaSignInComplete` (the generated request type carries
`turnstileToken` since #1162's regeneration). Error semantics are preserved:
5xx/unreachable/contract-drift → `AuthServiceUnavailableError`, 423 →
`AccountLockedError`, other 4xx → `CredentialsSignInError`; `requiresMfa`
challenges and one-time `mfaEnrollmentBackupCodes` still never enter the
session. The deprecated `signInPath` option is now ignored (no caller outside
tests used it); tests assert the served route is always used.

## F5 — the 7 "missing" Orders actions: verified deliberate, documented

The matrix classified `:cancel`/`:refund`/PATCH/DELETE/`:hold`/`:release`/HEAD
on `OrdersController` as VERSIONED-DIFF drift. They are **not live routes**:
`MinimumOrderRouteApplicationModelConvention`
(`GameGuild.API/Core/Conventions/MinimumOrderRouteApplicationModelConvention.cs:20-35`,
registered at `PresentationServiceCollectionExtensions.cs:66`) strips every
action lacking `[MinimumOrderRoute]` from the application model before routing
and OpenAPI generation, and
`OrdersController_ExposesOnlyVerifiedCheckoutActionsToMinimumComposition`
(`GameGuild.Commerce.Orders.UnitTests/ControllerAndInfrastructureTests.cs:434`)
pins the 7-action allowlist. The static controller scan behind the matrix
counted declared actions, not composed routes.

- Client currency: `.metadata.json` records regeneration 2026-11-02
  (`8c1287d2…`); the OpenAPI consistency lane is green on the latest develop-adjacent
  PR run (41812167882, 2026-11-04). Regenerating again is a no-op — the generated
  client already matches the served surface.
- No migration needed: `apps/web/src` fetches none of the 7 hidden actions by
  any transport (the marketplace lib already uses the generated module for the
  7 exposed ones).
- `docs/architecture/api-contract-matrix.md` F5/F6 sections and the headline
  counts are corrected so the backlog stops chasing phantom endpoints.

## Notes for reviewers

- `GeneratedApi` is a root-export namespace only; inside the package the fixes
  import the generated module classes (`AuthModule`,
  `AuthMultiFactorModule`, `CommerceProductsPromoCampaignsModule`) directly.
- The `next/headers`-based forwarded-IP interceptor in `createServerClient`
  no-ops outside a Next request scope, so the credentials provider stays
  runtime-agnostic.
