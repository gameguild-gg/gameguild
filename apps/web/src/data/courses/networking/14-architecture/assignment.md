## Overview

This is your **second and final in-class testing session**. By now your networked application should be feature-complete. Use this week to validate bug fixes from last week's feedback, stress-test under adverse network conditions, and gather final polish notes.

## What to Prepare

- An **updated build** with fixes applied from Checkpoint 4 feedback.
- An updated list showing which issues from last week were fixed and which remain.
- A plan for testing under degraded network conditions (high latency, packet loss, jitter).

## During Class

1. **Re-test** — Classmates re-test your project to verify fixes.
2. **Stress testing** — Test under adverse conditions: add artificial latency (200ms+), packet loss (5%+), and jitter (50ms+). Document what breaks.
3. **Final feedback round** — Collect one last round of feedback focusing on reliability, edge cases, and performance.
4. **Feature freeze commitment** — After this session, lock your feature set. Any remaining work is bug fixes, polish, and documentation only.

## Deliverables

1. Updated testable build with bug fixes applied.
2. Summary of improvements made since Checkpoint 4.
3. A final prioritized list of remaining polish items (bugs only — no new features).
