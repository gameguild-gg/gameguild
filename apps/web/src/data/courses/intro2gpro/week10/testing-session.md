# Testing Session

## Publishing the Game on itch.io

If you used this [Unity template](https://github.com/gameguild-gg/UnityBoilerplate/), you can download the `gh-pages` branch on GitHub as a ZIP; it will contain the built game. Go to your fork, open the branch dropdown, select `gh-pages`, and download the ZIP.

If you use another engine, export a WebGL build and ZIP it.

With the ZIP ready, upload it to itch.io:

1. Go to the jam page: [https://itch.io/jam/gpr100-25](https://itch.io/jam/gpr100-25)
2. Join the jam.
3. Click Upload and select your ZIP file.
4. Fill in the game name and confirm the upload.

## Objective

Prepare a minimum-functioning prototype focused solely on your game’s core mechanic for the upcoming QA test round.

## Guidelines

### Focus on Core Mechanic
- Identify and isolate the primary action or feature that defines your game (movement, key interaction, unique gameplay element).
- Build a basic prototype that showcases this mechanic; prioritize clarity and functionality for testing.

### Build a Playable Prototype
- Ensure the prototype is playable and clearly highlights the core mechanic.
- Avoid additional features or art that distract from the main mechanic.
- Aim for simplicity—no levels, polish, or complex graphics required at this stage.

### User Experience
- Add clear instructions or visual guides so testers understand how to interact.
- Ensure controls are intuitive and responsive.

### Prepare for QA Testing
- Be ready to receive feedback on the core mechanic; note assumptions about player interaction.
- Write a few specific tester questions (e.g., “Does this feel responsive?” “Is it clear how to perform the main action?”).

## Preparation
- Ensure your game is in a playable state.
- Review the build instructions (we use GitHub in our scenario): [https://confluence.champlain.edu/display/GSP/Making+a+build](https://confluence.champlain.edu/display/GSP/Making+a+build)
- Prepare the URL or ZIP build of your game.
- Write questions for a feedback form (Google Forms or equivalent).
- The form should explain the game, controls, and testing goals—or include a short in-game tutorial.
- Share the form with me so I can grade it.
- In class, we will run a playtesting session; you will playtest peers’ games and provide feedback.

## Playtesting
- At the beginning of class, developers select a station (island or pod) to set up the game and feedback form.
- Half of the students are testers; the other half are developers.
- As a tester, play each game for 5 minutes and provide feedback for every game.
- Read the provided documentation, play the game, and answer the questions in the Canvas comment section.
- Be precise and kind when writing feedback. Misbehavior will be addressed and may be reported.
- Developers may clarify instructions only if testers are stuck. Do not provide hints or tips.

## Submission
- The game URL or ZIP.
- The feedback form shared with me.

## Example Feedback Form

Create a text section in your form:

- Game: Stardew Valley
- Controls: Use mouse and keyboard (WASD) to move and interact
- Testing Goals: Explore the environment and try to break the seeding mechanic

Then add questions:

1. How do you feel about the seeding mechanic? Is it enjoyable?
2. Rate the seeding mechanic from 1 to 5.

I will grade the feedback given, the game delivery, and the quality of your questions.
