# Field-level read-capture surface extension (issue #186 criterion 1)

## Context

The field-access capture core landed in #1027: universal write capture inside
`ApplicationDbContext.SaveChangesAsync` (one `FieldAccessAudit` row per changed field of every
persisted write) plus read capture on `[DataMaskingResourceType]` endpoints. Re-verification of
issue #186's eight open boxes against develop confirmed all eight are implemented — but the read
side of criterion 1 ("tracking for **all** database entities") was bound to a genuinely narrow
surface: `UsersController` was the only controller carrying `[DataMaskingResourceType]`.

## What this PR does

Extends the field-level **read** capture surface to the remaining controllers whose responses
carry classifier-detectable data-subject PII:

| Controller | Resource type | Classifier-detectable fields |
|---|---|---|
| `UserProfilesController` | `UserProfile` | `DisplayName`, `AvatarUrl` |
| `SupportTicketsController` | `SupportTicket` | `ReporterEmail` (agent-facing ticket views) |
| `MySupportTicketsController` | `SupportTicket` | `ReporterEmail` (customer self-service) |

Masking stays decoupled: `DataMaskingService` resolves DB-configured rules per resource type and
is a no-op for a resource type until an admin configures rules, so the annotation cannot change
existing response payloads; only read capture activates immediately, via the already-registered
global `FieldAccessReadCaptureFilter`.

## Tests

In `FieldAccessReadCaptureFilterTests`:

- `SupportTicketSurface_RecordsReporterEmailReadsFromTicketResponses` — capture through a real
  `SupportTicketDto` response; bare person names are not flagged (classifier-consistent).
- `UserProfileSurface_RecordsDisplayNameAndAvatarUrlReads` — capture through a real
  `UserProfileDto` response.
- `PiiReturningControllers_AreAnnotatedForFieldLevelReadCapture` — reflection guard pinning the
  annotated surface set so regressions cannot silently disable read tracking for a surface.

Compile verified via the build gate (compile-only per INC-PG hold); CI executes the test suites.

Refs #186 (criterion 1 read-surface breadth; boxes 2-8 already delivered on develop and verified
separately).
