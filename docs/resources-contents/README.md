# GameGuild.Resources.Contents — Documentation Package

> Module `GameGuild.Resources.Contents` (polymorphic content versioning + document-template contract generation) · Documented against `develop` commit `ce31d5850c` (merge of #1311).
> Scope: the `ContentVersion` lifecycle (draft → review → approval → publish/schedule/archive with rollback, comparison, review comments), the `DocumentTemplate` render engine, and contract generation that stamps rendered templates into content versions. **The package's central deliverable is the reconciliation of the E9 not-found→500 / EF-translation failure findings for the whole `api/contents/versioning` surface (issue #1278 round-2 sweep, baselined 2026-11-04)** against what the code actually does. **Not** in scope: `GameGuild.Content.Pages` (CMS pages — `docs/content/`) and `GameGuild.Resources` (Platform assets family — `docs/social-platform/`).

## Module shape at a glance

- **22 .cs files** under `Contents:/`: 2 controllers (`VersioningController` 16 routes, `ContractGenerationController` 2 routes), 12 command records (10 versioning + 2 contract-generation) **all with handlers**, 6 services (facade `ContentVersioningService` over `ContentDraftService` / `ContentReviewPublishingService` / `ContentVersionQueryService`, plus `DocumentTemplateService` / `ContractGenerationService`), 3 entities (`ContentVersion`, `ContentVersionReview`, `DocumentTemplate`), 3 entity configurations + `ContentsModelConfiguration`, module class `ContentsModule : IModule`.
- **Tables (3, default schema)**: `content_versions`, `content_version_reviews`, `document_templates` — materialized in `20260814193823_ReconcileApplicationModel` (re-anchored by `20260824180312_AddEconomyProductionPlatform`); configs apply via `ContentsModelConfiguration : IModelConfiguration` (`Contents:/Configuration/ContentsModelConfiguration.cs`) discovered by `ApplicationDbContext.OnModelCreating` assembly scan (`API:/Database/ApplicationDbContext.cs:866-883`).
- **Wiring**: registered the legacy way — `new ContentsModule().ConfigureServices(...)` (`API:/Core/Setup/InfrastructureLayerExtensions.cs:255-258`); versioning handlers resolve via the CQRS assembly scan (`API:/Core/Setup/ApplicationLayerExtensions.cs:142`; module listed in `CommonEnabledModules`, `API:/Core/Setup/ModuleConfiguration.cs:37`); the two contract-generation handlers are *also* explicitly registered in `ContentsModule.cs:22-23`. `MapEndpoints` is an empty pass-through (`ContentsModule.cs:35-39`) — all routing is attribute-based.
- **Route style outlier**: `VersioningController` is the module's only controller on the **legacy unversioned prefix** `api/contents/[controller]` (`Controllers/VersioningController.cs:12`) — it does not ride `v{version:apiVersion}` and carries no `[ApiVersion]`; `ContractGenerationController` does (`Controllers/ContractGenerationController.cs:10-12`).
- **Auth**: `[Authorize]` on both controllers; code-level editorial gates (`content:draft|write|admin`, `content:schedule|write|admin`, `content:edit|write|admin`, `Controllers/VersioningController.cs:22-24`) on **5 of 16** versioning routes — submit/approve/reject/publish/reviews are gated by nothing beyond `[Authorize]`. `GetCurrentVersion` is `[AllowAnonymous]` (`:122`). Rate limit: `global` policy only.
- **Tenancy**: none — `ContentVersion` rows are keyed by polymorphic `(EntityId, EntityType)` with no tenant predicate anywhere; the only global query filter is `!IsDeleted` (`Configuration/ContentVersionEntityConfiguration.cs:34`).

## Headline findings

1. **The versioning surface is dead at runtime — 16 of 18 routes 500** (KNOWN, baselined). E9 round 2 (2026-11-04, issues #1184-family / #1278 class 2) recorded every read and transition route of `api/contents/versioning/*` as `EF query translation failure (unmapped member) -> 500` — `Baseline:` lines 170-176 (7 GETs), 225-232 (8 POSTs), 280 (PUT drafts). The common predicate in every failing query is `!v.IsDeleted` over the computed `EntityBase.IsDeleted` getter (`DeletedAt.HasValue`, `SharedKernel/Entities/EntityBase.cs:40`). Only `POST drafts` (E9-clean, likely via its validation/gate path) and the `v1/document-contracts/*` pair are absent from the failing set. Full mapping: `02-cqrs-wiring-matrix.md` §3.
2. **Cancel-schedule can never succeed** (NEW, latent under R1). `CancelScheduledPublishAsync` guards on `Status == Scheduled` and then calls `version.Approve(...)` (`Services/ContentReviewPublishingService.cs:222`) — but the entity's `Approve` requires `PendingReview` and throws otherwise (`Entities/ContentVersion.cs:166-169`); unlike its siblings, the cancel path has **no try/catch**, so even with the EF issue fixed the route 500s on every well-formed request. The test suite names the bug without fixing it: `CancelScheduledPublishAsync_WhenScheduled_ThrowsDueToMissingEntityMethod` (`tests/.../Services/ContentReviewPublishingServiceTests.cs:398`).
3. **Scheduled publishing has no worker** (NEW). `ProcessScheduledPublishingAsync` (`Services/ContentReviewPublishingService.cs:230-272`) has zero callers — no route, no `IHostedService`, no entry in the background-workers inventory. A version scheduled for the future stays `Scheduled` forever unless an operator manually `POST …/publish` (the entity does accept Scheduled→Published, `Entities/ContentVersion.cs:193`).
4. **DocumentTemplate has no API surface** (NEW). `DocumentTemplateService.Create/Update/List/GetPublished` (`Services/DocumentTemplateService.cs`) have no controller; no seeder touches `document_templates`; `IDocumentTemplateService` has no consumer outside the module beyond `ContractGenerationService.RenderPublishedAsync`. In any real environment `POST v1/document-contracts/generate` can only answer `DocumentTemplate.NotFound` / `PublishedVersionNotFound` — the feature is test-only as wired.
5. **Zero observability contract** (NEW). No `IContentPagesAuditEventSink`-style port here: publishing, approving, rolling back and generating contracts leave **no audit trail** — only `ILogger.LogInformation` lines (`Services/ContentDraftService.cs:46`, `ContentReviewPublishingService.cs:32,56,80,166,197,225,259`). Contrast Content.Pages (fail-closed audit per mutation) — see `04-event-inventory.md`.
6. **The `[AllowAnonymous]` current-version route is mis-allowlisted** (NEW). `VersioningController.GetCurrentVersion` is anonymous (`Controllers/VersioningController.cs:122`) and matches the registry entry `["VersioningController.GetCurrentVersion"]` whose justification reads *"Build/version probe used by load balancers; exposes only the version"* (`API:/Security/AnonymousEndpointRegistry.cs:44`) — written for a controller that no longer exists. The endpoint actually returns full published content bodies (`Title/Summary/Body/Metadata`) for any `(entityType, entityId)` pair.
