## Headline findings

1. **The incremental-progress pipeline is dead** — `AchievementService.UpdateProgressAsync` (`Ach:/Services/AchievementService.cs:76-128`) implements get-or-create progress, `IncrementProgress`, and auto-award-on-completion, but **no caller exists anywhere** (grep `UpdateProgressAsync` over `Source/` hits only the interface and Learning/Courses' unrelated method). `AchievementProgress` rows can never be created through any route or handler; levels and their tier progression are equally write-orphaned — the `POST /api/achievements` handler never constructs `AchievementLevel`s (`Ach:/Commands/AchievementCommands.cs:52-77`). The module is a manual-award badge box; everything "gamified" about it is unreachable (G1).
2. **The admin surface is permission-gated on keys nobody seeds** — `achievements:create/update/delete/award` appear only in `Ach:/AchievementsPermission.cs:6-11`; the `PolicyDefinitionSeeder` defines/seeds no such permissions, so the resource-permission engine denies every caller. Achievements cannot be created, updated, deleted, or awarded through the API until the keys are seeded and granted (G2).
3. **Secret achievements leak by id and by eligibility** — `GetAchievementByIdAsync` (`Ach:/Services/AchievementService.cs:235-241`) has no `IsSecret` filter and the by-id route is `[AllowAnonymous]` (`AchievementsController.cs:183-195`); `GetEligibleAchievementsAsync` (`:130-165`) loads all active achievements **including secrets** into the eligible list. The `includeSecrets:false` guard exists only on the catalog list (`:243-274`) — two of three read paths disclose secret definitions (G3).
4. **Non-repeatable awards have a check-then-insert race with no unique constraint** — the duplicate check (`AchievementService.cs:40-49`) queries then inserts without transaction or unique index; `user_achievements` has an explicitly **non-unique** `(UserId, AchievementId)` index ("Allow repeatable achievements", `Ach:/Entities/UserAchievement.cs:17`). Concurrent awards double-grant points (STRIDE 2.2).
5. **The module never notifies anyone** — 8 declared domain events are never constructed (`Ach:/Events/AchievementEvents.cs` — zero construction sites); no Notification row is ever created with `NotificationType.AchievementUnlocked` (grep over `Source/` — only the enum and the preference toggle reference it). The notify path is client-side polling of `my/unnotified` + `mark-notified` (`AchievementsController.cs:86-135`), a handshake with no server-side delivery (04/05; STRIDE family 4).
