## Conventions

- Follows the merged auth/payments doc conventions (`docs/auth/flows/*`, `docs/commerce/payments/*`): file:line on every node, `L###` shorthand inside Mermaid labels, edge-case matrices as tables, honest gaps section.
- Mermaid labels contain no parentheses and no colons (repo rendering constraint); route custom actions are spelled `id-colon-action` when a file:line is not enough.
- Citation shorthand: `Core:` = `apps/api/Source/Modules/GameGuild.Finance.Economy/`, `AdRewards:` = `.../GameGuild.Finance.Economy.AdRewards/`, `Marketplace:` = `.../GameGuild.Finance.Economy.Marketplace/`, `Payouts:` = `.../GameGuild.Finance.Economy.Payouts/`, `Bounties:` = `.../GameGuild.Finance.Economy.Bounties/`, `Treasury:` = `.../GameGuild.Finance.Economy.Treasury/`, `AiCredits:` = `.../GameGuild.Finance.Economy.AiCredits/`, `API:` = `apps/api/Source/GameGuild.API/`.
- The durable PostgreSQL writer functions live in `API:/Database/Migrations/20260824180312_AddEconomyProductionPlatform.cs` (the `economy_private.*` function family); they are cited as `Migration:` with a character-anchor note because the SQL bodies are single-line strings (e.g. `post_marketplace_refund_v1` body begins ≈ line 18 / char 864,830 of that file).
- Tests live in `apps/api/tests/GameGuild.Finance.Economy.UnitTests/` (+ `.AdRewards/`, `.AiCredits/`, `.Bounties/`, `.Marketplace/`, `.Payouts/`, `.Treasury/` unit-test projects; shared fixtures in `GameGuild.TestSupport.Finance.Economy/`). There is no Economy integration-test project — Economy endpoints are exercised through `GameGuild.API.IntegrationTests/` only where present (see `02-cqrs-wiring-matrix.md` HOLE column).

## Module shape at a glance

- **Controllers (19)**, all in `API:/Core/Controllers/`: EconomyWallet (self-service surface incl. transfers/top-ups/payout requests), EconomyPayoutExecution (file holds three: self-service onboarding/account, payout-requests admin execution, Stripe Connect webhook), EconomyPayoutAdministration (request review), EconomyTreasuryAdministration, EconomyMarketplace (self-service + administration), EconomyBounties (self-service + administration), EconomyAdRewards (self-service + administration), EconomyKyc (+ SumSub webhook), EconomyControlPlaneAdministration, EconomyComplianceAdministration, EconomyComplianceHoldAdministration, EconomyRiskReviewAdministration, EconomyLegacyMigrationAdministration, and four read-only query administration controllers (Ledger, Policy, Reserve, AdReward, Marketplace).
- **Sub-modules**: core ledger (`Core:` — Money, Ledger, Posting, Projections, Funding, Transfers, Risk, Reserves, Policy, Operations, Writer), AdRewards (14 tables), Marketplace (10), Payouts (5), Bounties (4), Treasury (4), AiCredits (3) — 108 tables total per the #1092 analysis.
- **Hosted service (1)**: `EconomyDurableWorker` (`API:/Core/HostedServices/EconomyDurableWorker.cs:30`) drives every background loop: capability activation, journal integrity, bounty expiration, marketplace outbox (safety cycle, on by default), payout + treasury dispatch outboxes (dispatch cycle, **off by default** — `DispatchWorkersEnabled` defaults false at `:17`), anchor publish/verify (off by default at `:18`).
- **Permissions**: 13 `economy:*` typed permissions (`Identity.Authorization/Models/TypedPermissions.cs:931-944`) — the matrix in `02` maps each to its endpoints.
- **Provider seams**: Stripe funding (`Core:/Integrations/StripeEconomyTopUpProvider.cs` + `StripeEconomyTopUpEventConsumer.cs`), Stripe Connect payouts (`Payouts:/StripeConnectPayoutProvider.cs`), Stripe platform treasury (`Treasury:/StripePlatformAdminWithdrawalProvider.cs`), ad networks (`AdRewards:/AdRewardProviderAdapters.cs`), SumSub KYC (`API:/Core/Controllers/EconomyKycController.cs` + `API:/Core/Integration/EconomyKycEvidenceStore.cs`).
- **Auth step-up**: every protected mutation on the admin execution surface flows through `EconomyStepUpExecutor` (`API:/Core/Authorization/EconomyStepUpExecutor.cs:49`) — a Serializable transaction that consumes a fresh step-up receipt bound to (operation type, target reference, payload hash) before running the protected action.
