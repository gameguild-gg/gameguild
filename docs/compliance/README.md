## Headline findings

1. **The entire Consent module API is dead at runtime** — `AddConsentModule` (`Consent:/Extensions/DependencyInjection.cs:7`) is never called by the host; handlers are registered by module scan (`API:/Core/Setup/ModuleConfiguration.cs:23`) but `IConsentService` cannot resolve, so every `api/compliance/consent` endpoint 500s (`07-gaps.md` N1). **Re-verified 2026-11-04 at develop 21b58ac6a7 — still live.** PR #1268 (Consent wiring + FERPA ownership + server-side processor ids + deadline sweepers) is open and unmerged; merge it before citing any of N1/N2/N4/N5/N6 as fixed.
2. **Re-granting a revoked consent is a guaranteed 500** — unique index `(UserId, PolicyVersionId)` (`Consent:/Entities/ConsentEntities.cs:88`) collides with the insert path taken when the existing row is revoked (`Consent:/Services/ConsentService.cs:53-67`) — N2.
3. **Authorization asymmetry**: the Audit module runs a three-layer model (policy + DAC permission + tenant clamp), while Consent, FERPA and the SumSub webhook run bare `[Authorize]` with no permission, no ownership check, and no rate limit — any authenticated user can read any student's education records, revoke their consents, or complete their inspection requests (N4/N5, `06-security-analysis.md`).
4. **KYC document upload is a stub** — `UploadDocumentAsync` ignores the stream and returns a fabricated path (`Kyc:/Services/KycService.cs:191-204`, `// PLANNED`), while the SumSub pipeline keeps its own signed evidence — two KYC ledgers with no bridge between them (N7).
5. **Audit durability is genuinely strong**: taxonomy-classified security events with bounded retries, disk spool with replay, PII-redacted fail-safe fallbacks, per-tenant ECDSA-signed hash chains, and legal holds honored by every purge worker — the package documents the machinery and its residual edges (spool poisoning, `SecurityEventSpoolingDisabled` after both legs fail).
