## Headline findings

1. **20 dead request types** — 13 commands and 7 queries are declared in `Ledgers:/Commands/LedgerCommands.cs` and `Ledgers:/Queries/LedgerQueries.cs` with **no handler anywhere** (only 7 commands + 18 queries have handlers). The dead set includes the entire ledger-mutation lifecycle (update/move/status/budget/delete), the whole virtual-ledger write surface, batch posting, reconciliation, and stats refresh. Full reconciliation with "what it was meant to do / what's reachable / hole or planned" per type: `02-cqrs-wiring-matrix.md` §3; gap entry L1.
2. **The module README is fiction relative to the code** — it documents ~40 routes (move, status, batch, `ledger-transfers`, full virtual-ledger CRUD) of which 24 exist; 16 documented routes are dead (`Ledgers:/README.md:83-135`). Anyone integrating against the README instead of the OpenAPI surface will build on routes that 404/405 (L2).
3. **The one integration event publishes to nobody** — `finance.ledger-entry.posted.v1` rides the platform outbox with validator and dedup, and zero consumers subscribe (L3) — the same no-consumer family as economy N1/N2.
4. **Rollup caches exist but nothing refreshes them** — `Ledger.CachedNetBalance/CachedEntryCount` are denormalized stats (`Entities/Ledger.cs:119-135`), `UpdateCachedStats` exists (`:360-367`), and the refresh commands (`RefreshLedgerStatsCommand`, `RefreshSubtreeStatsCommand`) are among the dead 20; live balance/rollup endpoints recompute from entries, so the caches are write-orphaned decoration (L4).
5. **The Economy "double-entry" is a different ledger** — `GameGuild.Finance.Economy` keeps its own `economy_journal` behind SECURITY DEFINER writer functions (the economy package's §4 integrity chain); `Finance.Ledgers` is a managerial/analytic hierarchy with paired transfer legs but **no balanced-ledger invariant** (a single-sided `PostEntryCommand` needs no counterparty). The two share no tables, no events, and no bridge — the boundary contract is documented in `05-cross-module-sequences.md` §3 so the next auditor does not merge them.
